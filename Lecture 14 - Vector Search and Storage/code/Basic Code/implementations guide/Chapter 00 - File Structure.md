# Chapter 00 — File Structure

**Goal:** Understand where every file lives and what role it plays before reading any single file. Follow the chapters in order (00 → 07).

## Full file tree

```
code/Basic Code/
├── .env                    # runtime environment variables (PORT)
├── package.json            # npm manifest: scripts + dependencies
├── package-lock.json       # locked dependency versions (generated by `npm install`)
├── tsconfig.json           # TypeScript compiler settings
├── dist/                   # compiled JavaScript output (generated by `npm run build`)
└── src/                    # TypeScript source (hand-written)
    ├── index.ts            # entry point: creates app, mounts routes, starts server
    ├── config/
    │   └── config.ts       # reads PORT from env
    ├── types/
    │   └── index.ts        # VectorRecord + SearchResult interfaces
    ├── services/
    │   └── vectorService.ts# in-memory vector store + brute-force KNN + cosine similarity
    ├── controllers/
    │   └── vectorController.ts # HTTP handlers: POST /vectors, GET /search
    └── routes/
        └── index.ts        # Express router wiring endpoints to controllers
```

## What each folder does (one relevant file per folder)

| Folder | File | Role |
|--------|------|------|
| (root) | `.env` | `PORT` the server listens on |
| (root) | `package.json` | scripts (`build`, `start`, `dev`) and the `express` dependency |
| `src` | `index.ts` | Bootstrap: `express()`, JSON body-parser, mount routes, `listen()` |
| `src/config` | `config.ts` | Reads `process.env.PORT`, default `3000` |
| `src/types` | `index.ts` | `VectorRecord` (id + embedding + metadata) and `SearchResult` |
| `src/services` | `vectorService.ts` | The core: in-memory store, `cosineSimilarity`, `addVector`, `searchVectors` (brute-force KNN) |
| `src/controllers` | `vectorController.ts` | `POST /vectors` (store) and `GET /search` (top-K) handlers |
| `src/routes` | `index.ts` | Express `Router` mapping paths to controller functions |

## Why this shape
The notes say a vector database record is **ID + vector + metadata**, and the search algorithm is **score → sort → top-K** (the brute-force baseline). One file per concern keeps the code minimal and easy to follow: types → config → service → controller → routes → entry.

## Commands used in this guide

| Command | Purpose |
|---------|---------|
| `npm install` | install `express` + dev dependencies (creates `package-lock.json`) |
| `npm run build` | compile TypeScript to `dist/` |
| `npm start` | run the compiled server |

**No `middleware` folder:** the notes don't require auth, logging, or error handling for this basic baseline, so it is intentionally left out. Add it only when a later lecture or the notes require it.
