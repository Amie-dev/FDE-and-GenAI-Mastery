### Block by block

**`"type": "module"` + `"module": "NodeNext"`.** The project is ESM, so every relative import must carry a
`.js` extension even though the source is `.ts` (`import { config } from '../config/config.js'`). That looks
wrong the first time and is correct: the compiler emits `.js`, so the specifier must already be `.js`.

**The four runtime dependencies, and nothing else.**

| Package | Why it is here | Why nothing bigger |
| :--- | :--- | :--- |
| `express` | the HTTP layer; `res.write()` + `flushHeaders()` are all streaming needs | No framework abstractions — chapter 07 §07.4 says the *return type* is the architecture, and `res` is the honest version of it |
| `openai` | one real provider call in LIVE mode, speaking the OpenAI dialect (chapter 05 §05.4) | Any OpenAI-compatible endpoint works by changing `AI_ENDPOINT` |
| `zod` | validate the `.env` **and** the request bodies | Chapter 02 §02.8 — the request shape is the first thing to reject |
| `dotenv` | load `.env` | Node 20.6+ can do this natively, but dotenv matches the other lectures |

**No `gpt-tokenizer`.** Chapter 09 §09.5 offers the characters ÷ average-chars-per-token estimator as the
"±10–15%, free" option, and this lab takes it — see `estimate` in `lib/llm.ts`. That keeps the dependency
list to four and makes the "estimate during, reconcile at the end" point visible instead of hidden behind a
library.

**`tsx` for dev, `tsc` for build.** `tsx watch` gives an instant reload loop; `npm run build && npm start`
proves the compiled artifact works, which the end-to-end chapter verifies.

## 1.4 `tsconfig.json` (full file)

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "lib": ["ES2022"],
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
```

### Block by block

| Setting | Effect | Notes reason |
| :--- | :--- | :--- |
| `target: ES2022` | native `AsyncGenerator`, `AbortController`, top-level `await` | The whole lecture is built on async iteration (chapter 07 §07.3) |
| `module/moduleResolution: NodeNext` | real ESM resolution, `.js` specifiers | Keeps `import`/`export` semantics identical to the compiled output |
| `lib: ["ES2022"]` | **no `DOM`** | `TextDecoder`/`TextEncoder` come from `@types/node`, not from the DOM — the same API the browser has, which is the point of chapter 04 §04.4 |
| `strict: true` | `noImplicitAny`, `strictNullChecks`, … | `TTFT` is `number \| null` on purpose: a stream with zero deltas has *no* TTFT, and the type says so |
| `outDir: ./dist`, `rootDir: ./src` | mirrors `src/` into `dist/` | `express.static(path.join(here, '..', 'public'))` resolves from both `src/` and `dist/` |

## 1.5 `.env` (full file)

```dotenv
# ---- HTTP -------------------------------------------------------------------
PORT=8097

# ---- Model (chapter 01 §01.3, chapter 07 §07.1) -----------------------------
AI_PROVIDER=openai
AI_MODEL=gpt-4o-mini
AI_TEMPERATURE=0.3
AI_MAX_TOKENS=400

# ---- Delivery policy: the stream pump (chapter 07 §07.6) --------------------
FLUSH_INTERVAL_MS=40
FLUSH_BYTES=256

# ---- Keep-alive (chapter 05 §05.3.3) ---------------------------------------
HEARTBEAT_MS=15000

# ---- Simulated cadence for OFFLINE mode (chapter 01 §01.3) -----------------
OFFLINE_TTFT_MS=250
OFFLINE_ITL_MS=25

# ---- Request shape (chapter 02 §02.8) --------------------------------------
MAX_INPUT_CHARS=8000

# ---- Credentials -----------------------------------------------------------
# Empty key = OFFLINE mode: every endpoint still works against a stub.
OPENAI_API_KEY=
GROQ_API_KEY=
OLLAMA_BASE_URL=http://localhost:11434/v1
```

### Block by block

**`AI_MAX_TOKENS=400` is a delivery setting, not a model setting.** Chapter 09 §09.9 lists it as the lever
that bounds worst-case completion cost — and, just as importantly, bounds the *wait*: the longest possible
answer is now predictable, which is what makes a latency budget meaningful.

**`FLUSH_INTERVAL_MS=40` / `FLUSH_BYTES=256` are the coalescing policy from chapter 07 §07.6.** 40 ms is
under one 60 fps frame, so the batching is invisible; 256 bytes caps how long a very fast stream can wait
for a flush. Chapter 03 §03.3 gives the reason this is free: a human reads at roughly 8 tokens/second, so
there is no product value in writing one socket frame per token.

**`HEARTBEAT_MS=15000` is deliberately below 30 s.** Chapter 05 §05.3.3 recommends 10–15 s because 30 s is
the smallest idle timeout you will meet in the wild (load balancers), and a heartbeat only helps if it
always fires first.

**`OFFLINE_TTFT_MS=250` and `OFFLINE_ITL_MS=25` model the two phases of chapter 01 §01.3.** The first is the
parallel **prefill** that sets TTFT; the second is the serial **decode** step that sets ITL and therefore
TPS (1000 ÷ 25 = 40 tokens/s). With these two numbers the offline stub produces the same *shape* of latency
as a real provider, so every metric in chapter 03 is exercised without a key.

**`MAX_INPUT_CHARS=8000`** is the request-shape limit. It is enforced by Zod before the first byte, because
after the first byte a 400 is no longer possible (chapter 07 §07.7).

**An empty `OPENAI_API_KEY` is a feature, not a bug.** `isOffline()` in `lib/llm.ts` turns "no key" into a
deterministic stub, so every chapter is studyable with zero spend.

## 1.6 `.gitignore` (full file)

```text
# Dependencies & build output
node_modules/
dist/

# Secrets — never commit a real key
.env
.env.local

# Logs
*.log
```

### Block by block

`node_modules/` and `dist/` are generated. `.env` is git-ignored **and** duplicated as `.env.example`, which
is the only safe pattern: the example documents every key, and the real file never reaches the repository.
